- El /root se queda pillao
	- El bloqueo al intentar acceder al directorio `/root` en un entorno **PRoot** (como Termux en Android o chroot sin privilegios) se debe a un problema de permisos y pseudo-archivos o pipes colgados dentro del árbol de directorios del sistema de archivos virtual.
	- ### Causas más comunes
	- premio:: color
	- color:: gris
	-
	- **Permisos del directorio /root:** Por defecto, el directorio `/root` pertenece al usuario UID 0 con permisos estrictos (`700` o `750`). Si la aplicación GUI o el explorador de archivos intenta listar el contenido sin elevar contexto o sin mapeo correcto de UID en PRoot, el proceso entra en I/O Wait indefinido.
	- **Archivos especiales o montajes colgados:** PRoot emula llamadas al sistema (`ptrace`). Si `/root` o subdirectorios montados contienen sockets, pipes con nombre (`FIFO`), o puntos de montaje de pseudo-sistemas de archivos (`/proc`, `/sys`, `/dev`) que PRoot no maneja correctamente, el gestor de archivos se congela intentando leer metadata.
	- **Conflicto de sockets en aplicaciones GUI:** Gestores de archivos gráficos (como Thunar, PCManFM o Nautilus) intentan comunicarse con `dbus`, `gvfs` o servicios de papelera dentro de `/root/.local` o `/root/.cache`, bloqueando el hilo principal si los sockets de comunicación están truncados.
	- ### Soluciones rápidas
	- **Cambiar permisos a /root desde la terminal PRoot**
	  *Paso 1*
	  Abre una terminal dentro de tu entorno Manjaro PRoot y relaja los permisos del directorio para descartar bloqueos de acceso de lectura/ejecución:
	  
	  ```
	  chmod 755 /root
	  ```
	  
	  *Verificación:* Ejecuta `ls -ld /root` y confirma que los permisos muestren `drwxr-xr-x`.
	- **Limpiar cachés y sockets temporales**
	  *Paso 2*
	  Elimina archivos de bloqueo y sockets descolgados en la carpeta personal de root que suelen congelar los gestores de archivos GUI:
	  
	  ```
	  rm -rf /root/.cache/* /root/.local/share/trash/*
	  ```
	  
	  *Verificación:* Abre nuevamente tu explorador de archivos e intenta navegar hacia `/root`.
	- **Desactivar las vistas previas en el explorador de archivos**
	  *Paso 3*
	  Si usas un gestor gráfico (Thunar, PCManFM, etc.), entra en las preferencias de la aplicación y desactiva el **auto-montaje (GVFS)**, el **generador de miniaturas (thumbnails)** y la **muestra de tamaño de carpetas**. Esto evita que el explorador ejecute llamadas de escaneo profundo (`stat`) en pseudo-directorios de PRoot.
- Metodos alternativos para instalar logseq
	- Logseq can be installed on Manjaro through several alternatives that avoid Flatpak and `proot` limitations completely.
	- ### Comparison of Manjaro Logseq Packages
	  
	  | Method | Source | Performance / Sandbox | Recommendation |
	  
	  | **AppImage** | Official Logseq GitHub | Runs standalone, no install needed | Best for portability & simplicity |
	  
	  | **AUR (`logseq-desktop`)** | Arch User Repository | Native binary build | Best for system integration |
	  
	  | **Snap** | Canonical Snap Store | Sandboxed snap package | Alternative container option |
	- ### Option 1: AppImage (Easiest & Most Reliable)
	  
	  AppImages run natively on Manjaro without requiring root privileges or system daemons.
	  
	  ```
	  # 1. Download the latest AppImage release directly from GitHub
	  curl -s https://api.github.com/repos/logseq/logseq/releases/latest \
	  | grep "browser_download_url.*AppImage" \
	  | cut -d : -f 2,3 \
	  | tr -d \" \
	  | wget -qi -
	  
	  # 2. Make the file executable
	  chmod +x Logseq-linux-x64-*.AppImage
	  
	  # 3. Launch Logseq directly
	  ./Logseq-linux-x64-*.AppImage
	  ```
	  
	  **Verification:** Logseq should open immediately without needing any background services.
	- ### Option 2: AUR via Pamac (Native Arch Package)
	  
	  Manjaro's official user repository builds Logseq natively for your system.
	  
	  ```
	  # Install via Pamac from the Arch User Repository (AUR)
	  pamac build logseq-desktop-bin
	  ```
	  
	  *(Note: Use `logseq-desktop-bin` to download the pre-compiled binary instantly rather than building from source).*
	  
	  **Verification:** Launch Logseq by running `logseq` in your terminal or selecting it from your desktop application launcher.
	- ### Option 3: Snap Package
	  
	  If you already have `snapd` enabled on your Manjaro installation:
	  
	  ```
	  sudo snap install logseq
	  ```
	  
	  **Verification:** Run `snap list` to confirm `logseq` is listed, then open it via `snap run logseq`.
