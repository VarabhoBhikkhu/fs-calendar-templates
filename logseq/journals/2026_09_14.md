- how to run startup services in proot
	- Because PRoot runs entirely in user-space, traditional init systems like `systemd` or `openrc` cannot run directly inside a PRoot guest environment. Standard background processes or service managers must be started using command triggers or lightweight supervisors instead.
	- **Method 1: Run Services at Container Startup (`proot-distro login --`)** Execute commands automatically upon entering the PRoot container by using the `--` execution flag in your launch command:
	- # Example starting SSH and Cron in Ubuntu, then opening a shell
	- proot-distro login ubuntu -- bash -c "service ssh start && service cron start && exec bash"
	- To simplify startup, create a custom alias inside your host terminal (e.g., Termux `~/.bashrc`):
	- alias start-ubuntu='proot-distro login ubuntu -- bash -c "service ssh start; exec bash"'
	- **Method 2: Use `init` or `service` inside PRoot Shell** For distributions with traditional init scripts (like Debian or Ubuntu), manually manage services inside the running PRoot shell using standard commands:
	- # Start a daemon via sysvinit script
	- service apache2 start
	- # or
	- /etc/init.d/ssh start
	- **Method 3: Auto-Start Daemons via Shell Startup File (`~/.bashrc`)** Add background checks to the internal user shell configuration (`~/.bashrc` inside PRoot) so daemons start automatically upon login:
	- Log into your PRoot environment:
		- proot-distro login ubuntu
	- Append startup checks to your `~/.bashrc`:
		- # Check if process is running; if not, launch it silently in the background
		- if ! pgrep -x "sshd" > /dev/null; then
			- service ssh start > /dev/null 2>&1
		- fi
	- **Method 4: Supervise Daemons with `supervisord`** For running multiple background daemons reliably in PRoot, install a user-space process supervisor:
	- Install Supervisor inside the PRoot environment:
		- apt update && apt install supervisor -y
	- Launch Supervisor when logging into PRoot:
		- proot-distro login ubuntu -- bash -c "supervisord -c /etc/supervisor/supervisord.conf && exec bash"
	- **Method 5: Background Autostart from Android (Termux:Boot)** To launch a PRoot daemon automatically when your Android device reboots (without manually opening a shell):
	- Install the **Termux:Boot** app.
	- Create the boot script directory in Termux:
		- mkdir -p ~/.termux/boot/
	- Create a script (e.g., `~/.termux/boot/start-services.sh`) containing:
		- #!/data/data/com.termux/files/usr/bin/sh
		- termux-wake-lock
		- # Start background daemon inside PRoot container
		- proot-distro login ubuntu -- service ssh start
	- Grant execution rights:
		- chmod +x ~/.termux/boot/start-services.sh
- Why I cannot use flatpak or snap in proot distro
	- Neither **Flatpak** nor **Snap** are viable options inside a PRoot Linux environment on Android, because both rely heavily on low-level Linux kernel features that PRoot intentionally intercepts or lacks.
	- **Why They Do Not Work in PRoot:**
	- **Snap (`snapd`)** requires `systemd` running as PID 1, kernel loop devices (`/dev/loop*`), SquashFS kernel driver support, AppArmor, and full cgroups—none of which are available in user-space PRoot.
	- **Flatpak** relies on `bubblewrap`, system namespaces (`CLONE_NEWUSER`, `CLONE_NEWNS`), cgroups, and direct `OSTree` kernel mount capabilities. PRoot cannot establish nested container namespaces.
	- **Alternative Solutions for Package Management & Sandboxing**
	- If you are trying to run isolated or pre-packaged Linux applications inside Termux / PRoot, use these working alternatives instead:
	- **AppImage** AppImages package everything into a single executable file. While default AppImages call `FUSE` (which fails in PRoot), you can extract them or pass the `--appimage-extract-and-run` flag:
		- ./your-app.AppImage --appimage-extract-and-run
	- **Nix Package Manager** You can install the Nix package manager natively inside Termux or within a PRoot container to access huge repositories of isolated, reproducible binaries without needing root or kernel daemons:
		- # Can be installed directly in Termux or inside PRoot
		- sh <(curl -L https://nixos.org/nix/install) --no-daemon
	- **Chroot (Requires Rooted Android)** If you specifically need Flatpak or Snap, you must use a real `chroot` or Linux Deploy on a rooted Android device with a custom kernel built with loop device and SquashFS support, rather than non-rooted PRoot.
